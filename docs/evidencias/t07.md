# T07 - Datos adicionales y casos borde

Fecha base de los escenarios temporales: **13/11/2026**, zona horaria
`America/Argentina/Buenos_Aires`.

Los nueve archivos de `data/adicionales/` contienen diez filas propias cada uno.
Los identificadores usan el prefijo `D` para evitar colisiones con los originales:
`DC`, `DS`, `DF`, `DPRV`, `DPRD`, `DL`, `DRC`, `DV` y `DD`.

## Reglas de uso

- Los CSV de `data/original/` permanecen intactos.
- Los adicionales representan un recorte de la historia. `DRC010` (cliente
  `DC008`) se trata como una receta importada con una dispensa ya completada
  cuya venta quedó fuera del conjunto. Por eso q12 evalúa a `DC008` a partir
  de las ventas registradas en el dataset.
- Las ventas adicionales son historia ya consolidada. La carga conserva los
  saldos de stock y los estados de receta provistos.
- Los casos de rechazo se preparan mediante entidades inactivas, droguería o stock
  insuficiente; no se guardan ventas inválidas en los datos válidos.
- Para reproducir estos ejemplos desde Python, pasá `hoy=date(2026, 11, 13)`
  a las consultas que aceptan ese argumento. La CLI usa la fecha del sistema
  en Buenos Aires.

## Verificación reproducible

```sh
python scripts/loaders/load_mongo.py --dry-run
python -m unittest tests/test_datos_adicionales.py
python tests/carga/verify_mongo.py
```

El dry-run debe informar 18 clientes, 15 sucursales, 17 farmacéuticos, 15
proveedores, 23 productos, 28 lotes, 19 recetas, 26 ventas y 32 detalles: **193
registros en total**.

La carga se ejecutó dos veces sin duplicaciones. La sincronización final proyectó
**193 nodos de negocio y 247 relaciones** en Neo4j, tanto en la primera ejecución
como al repetirla.

# q04 · Clientes con más de una receta

`q04(db_mongo, sesion_neo4j)` recibe la base fuente de MongoDB y una sesión de
Neo4j. Refresca la proyección desde MongoDB y ejecuta la agregación en Neo4j.
Devuelve una lista de clientes con más de una receta registrada. Cada fila
incluye `id_cliente`, `nombre`, `apellido` y `cantidad_recetas`. La lista se
ordena por ID ascendente y queda vacía si nadie cumple el criterio.

Cypher recorre `(Receta)-[:PRESCRIPTA_A]->(Cliente)`, agrupa por cliente y
calcula `count(DISTINCT r.id_receta)`. Incluye recetas de todos los estados y
clientes inactivos que tengan más de una receta.

## Ejemplo verificado con los originales

Con la carga de MongoDB completada según el [README](../../README.md), ejecutá:

```sh
python3.12 scripts/run_query.py q04
```

En MongoDB 8.0.16 y Neo4j 5.26 se obtuvieron estas tres filas, en este orden.

| ID | Nombre | Apellido | Cantidad de recetas |
| --- | --- | --- | ---: |
| `C001` | Lucía | Fernández | 2 |
| `C002` | Martín | Gómez | 2 |
| `C006` | Ricardo | Paz | 2 |

- `C006` tiene `RC003` y `RC004`. `RC003` figura en `V006` y `V007` y cuenta una vez.
- `C002` cuenta `RC005` y `RC009`. `RC009` está vencida y carece de venta asociada.
- `C003`, con una receta, y `C005`, con ventas y cero recetas, quedan fuera.
- Al agregar una segunda receta a `C003` y marcar a la clienta como inactiva
  en MongoDB, el siguiente q04 la incluyó con cantidad `2`.
- Una base de prueba con un cliente y una receta devolvió `[]`. Con Neo4j
  indisponible, la CLI devolvió código `1`, un mensaje en stderr y stdout vacío.

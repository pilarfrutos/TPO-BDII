# q03 · Historial cronológico de un cliente

`q03(db_mongo, sesion_neo4j, id_cliente)` recibe la base de MongoDB, una sesión
de Neo4j y el ID del cliente como texto. Refresca el grafo desde un snapshot
de MongoDB y ejecuta la consulta en Neo4j antes de confirmar la proyección.
Busca el cliente por `$id_cliente` y recorre `REALIZADA_POR` desde las ventas
y `PRESCRIPTA_A` desde las recetas. Cada recorrido aporta sus propios eventos,+incluidas las recetas que todavía carecen de una venta asociada.

Para un cliente existente devuelve `id_cliente` y una lista de `eventos`. Cada
evento contiene `tipo`, `id`, `fecha` y `datos`. Los eventos se ordenan por
fecha ascendente, con receta antes que venta en la misma fecha y luego por ID
ascendente. La fecha de una receta es la de emisión. Las fechas salen en
formato `AAAA-MM-DD`. Se incluyen todos los estados de ventas y recetas.

## Ejemplo verificado con los originales

Con ambos motores preparados y la carga de MongoDB completada según el
[README](../../README.md), ejecutá:

```sh
python3.12 scripts/run_query.py q03 --id-cliente C001
```

En MongoDB 8.0.16 y Neo4j 5.26, la salida de `C001` tuvo estos seis eventos
en este orden. La tabla muestra los campos comunes y el estado de `datos`.

| Fecha | Tipo | ID | Estado |
| --- | --- | --- | --- |
| 2026-09-10 | receta | `RC001` | Completada |
| 2026-09-10 | venta | `V003` | Completada |
| 2026-09-25 | venta | `V015` | Anulada |
| 2026-10-02 | venta | `V013` | Completada |
| 2026-10-08 | receta | `RC008` | Completada |
| 2026-10-08 | venta | `V010` | Completada |

El evento de `V003`, por ejemplo, incluye el total en pesos y los IDs del
farmacéutico y de la receta.

```json
{
  "tipo": "venta",
  "id": "V003",
  "fecha": "2026-09-10",
  "datos": {
    "tipo": "Con receta",
    "estado": "Completada",
    "total": 9800,
    "medio_pago": "Obra social",
    "id_farmaceutico": "F001",
    "id_receta": "RC001"
  }
}
```

También se comprobó que `C002` incluye la receta vencida `RC009`, sin venta
asociada, y la venta pendiente `V012`. Un cliente temporal con dos recetas
del mismo día devolvió ambas una vez, ordenadas por ID. `C008`, inactivo y
sin historial, devolvió `{"id_cliente": "C008", "eventos": []}`. Un ID
inexistente devolvió `None` en Python y `null` en la terminal.

Un cambio en el medio de pago de `V003` apareció al volver a ejecutar q03.
Con Neo4j indisponible, el comando devolvió código `1`, un mensaje en stderr
y ninguna salida JSON.
